# SF ERP 系統規格 v2.0

> 2026-10-21 修訂：依輕量版實作更新特休半天單位、手動改日原因、特休追蹤起算日、請假總覽匯出 Excel、資料表欄位；
> 員工有紀錄時改以離職日處理、不能刪除；扣款以每筆紀錄登記當時的薪資計算。
> 請假總覽新增月結區間（上月 23 日 ～ 本月 22 日）與指定區間，匯出 Excel 比照辦理（第 11 節）。

## 1. 範圍
- 兩個量級，功能相同：
  - 輕量版 Lite：單一管理者在一台電腦上使用，不需登入
  - 標準版 Standard：公司內網多人使用，有登入與角色
- 功能：首頁與提醒、快速登記、出缺勤月曆、員工主檔、員工個人頁、請假總覽、備忘錄、制度與設定（含行事曆匯入、特休到期處理）
- 標準版另有：登入、帳號與角色
- 不含：簽核、員工自助申請、薪資結算、勞健保、所得稅
- 設計稿：https://claude.ai/artifact/Qxq262ApNCvEc1oEafwrba

## 2. 技術

### 2.1 兩版共用
- 前端：React 18 + TypeScript + Vite，兩版同一份程式碼；畫面只呼叫 DataSource 介面（輕量版接 LiteSource（sql.js），標準版接 ApiSource（REST））
- 規則（時數、扣款、特休、防呆）：TypeScript 與 Java 各一份，兩邊都要通過同一份測試案例 `rules-cases.json`
- 資料表結構相同（第 15 節），SQLite 與 PostgreSQL 各一套 migration
- 介面：預設深色，可切換淺色；語言可切換中文、English、日本語、한국어（預設中文）；主題與語言記在瀏覽器（每台電腦各自記住）

### 2.2 輕量版
- 交付 `SF ERP-lite.zip`：`index.html`（單一檔，JS、CSS、sql.js WASM 全部內嵌）、`data/`、`使用說明.txt`
- 以 Chrome 或 Edge 直接開啟 `index.html`（file://），不起任何服務、不開 port；其他瀏覽器顯示「不支援」畫面
- 第一次開啟時選擇資料夾，系統在裡面建立 `sf_erp.sqlite` 和 `backup/`；資料夾授權記在 IndexedDB，之後每次開啟按一次「允許存取」
- 每次修改後整檔寫回；寫入失敗時保留舊檔並提示
- 每天第一次存檔前，備份到 `backup/sf_erp-YYYYMMDD.sqlite`，保留最近 30 份
- 同一瀏覽器開第二個分頁時，第二個分頁改為唯讀；資料夾內另寫 `.lock` 檔，別台電腦開啟同一資料夾時先警告
- 可以一次匯入舊版 `data/db.json`（第 16 節）；可以匯出資料檔給標準版匯入

### 2.3 標準版
- 後端：Java 17、Spring Boot 3、Spring MVC（Controller → Service → Repository）、Spring Data JPA、Spring Security、Flyway
- 資料庫：PostgreSQL 16
- 部署：docker compose 部署到公司內網伺服器，三個容器：nginx（HTTPS、前端靜態檔、轉發 `/api`）、app、db
- 登入：帳號密碼，密碼以 BCrypt 儲存；Session Cookie（HttpOnly、SameSite=Strict）＋ CSRF token
  - 閒置 30 分鐘自動登出；勾選「保持登入」時為 8 小時
  - 連續 5 次密碼錯誤，鎖定 15 分鐘
  - 新帳號用臨時密碼，第一次登入時必須改密碼
- 權限：每支 API 以 `@PreAuthorize` 檢查角色；前端只負責隱藏用不到的按鈕
- 備份：每天 02:00 執行 pg_dump，保留 30 份
- 系統管理者可以匯入輕量版的 `sf_erp.sqlite`

## 3. 工時與扣款規則
- 上班 09:30～18:30，實際午休 12:00～13:30；午休只扣 1 小時，多出的 30 分鐘列為午休 bonus（13:30～14:00 這半小時以 1 小時計）；上午 2.5h、下午 5.5h、全天 8h
- 日薪 = 薪資 ÷ 30；時薪 = 日薪 ÷ 8（1 日以 8h 換算）
- 扣除金額 = 時數 × 時薪 × (1 − 給薪比例)；每筆紀錄存不取整的值，統計與匯出一律逐筆加總後才四捨五入到整數元一次（單筆在畫面上顯示四捨五入後的整數，所以畫面上各筆相加可能與合計差 1 元）
- 時數：一般假別為請假時段與工作時段的重疊時數（扣除午休，13:30～14:00 另加午休 bonus 30 分鐘）；特休以半天為單位，上午、下午各 4h，全天 8h；遲到從 09:30 算到實際到班時間，依實際分鐘數
- 每筆紀錄存檔時記下當時的月本薪與算好的扣除金額；之後調薪不回溯。編輯舊紀錄時以該筆登記當時的月本薪重新計算；若編輯時改成另一位員工，才改用該員工目前的月本薪

## 4. 行事曆
- 上傳「政府行政機關辦公日曆表.xlsx」，系統自動產生該年度每天的上班日／放假日（輕量版在瀏覽器內解析）
- 以格子的底色判斷放假日；年度從標題「西元 XXXX 年」讀取
- 可以手動把某天改為上班日或放假日，改過的日子會標示「手動」，並可以「還原為政府日曆」
- 重新上傳同一年度時，手動改過的日子不會被覆蓋
- 該年度還沒匯入行事曆時，不能登記

## 5. 首頁
- 今天日期，以及今天是上班日或放假日
- 數字卡：在職員工數、本月請假時數、本月扣除金額、待處理件數
- 待處理提醒：
  - 特休到期前 N 天內（預設 30，可在設定改）且剩餘 > 0：顯示員工、週年期間、剩餘時數、到期日，按鈕「換錢（顯示金額）」「遞延一年」「歸零」；遞延額度只顯示「換錢」
  - 下一年度行事曆尚未匯入（每年 10 月 1 日起提醒）：顯示「上傳 xlsx」
- 今天不在座位：當天所有紀錄
- 本週：週一到週五每天的請假人數
- 提醒於開啟首頁時即時計算（兩版相同）

## 6. 快速登記
- 一張假單登記一天：日期（預設今天）、員工、假別、時段、理由（選填）
- 多日請假：設定「起始日」與「結束日」（晚於起始日時）即可一次登記多天；遲到不適用，月曆編輯既有紀錄仍是單日
  - 起訖日之間每個上班日各存一筆；放假日自動略過，並顯示「略過 N 天放假日」
  - 第一個上班日用「第一天時段」，最後一個上班日用「最後一天時段」（各自可選全天／上午／下午／自選），中間的上班日一律全天；只有一個上班日時用第一天時段
  - 一次最多 92 天；結束日不能早於起始日
  - 逐日檢查，前面幾天的特休用量、時段會算進後面幾天；任何一天不能登記，整批不登記，錯誤訊息指出是哪一天與原因
  - 試算與確認畫面顯示合計時數、扣除金額與登記筆數；「這次已登記 N 筆」依實際筆數累計
- 員工下拉選單：只列出當天已到職且未離職的員工
- 假別下拉選單：顯示給薪比例；選到男性員工時不列出生理假
- 時段：
  - 特休：只能選全天、上午、下午（上午、下午各算半天 4h，全天 8h）
  - 遲到：起固定 09:30，填實際到班時間（09:31～18:30）
  - 其他假別：全天／上午／下午快速鍵，或自選起訖（每 30 分鐘一格）
- 即時試算：時數、時薪、給薪比例、扣除金額；特休另外顯示「剩餘 前 → 後」
- 防呆同第 7、8 節；放假日不能送出，錯誤訊息直接顯示在假單上
- 送出：
  - 假別開啟「雙重確認」時，先進確認畫面（員工、日期、假別、時間、時數、扣除金額；特休另列剩餘時數），按「確認送出」才存檔，也可以「返回修改」
  - 沒開雙重確認時直接存檔
- 成功畫面：顯示摘要，提供「再登記一筆」（保留日期、清空其他欄位）和「到月曆看這天」
- 頁面顯示「這次已登記 N 筆」

## 7. 出缺勤月曆
- 選擇年月（預設本月）；可切換「月曆」與「人員矩陣」；可篩選「只看某位員工」
- 月曆：週一開始；放假日灰底，今天的日期加圓圈；每格顯示當天請假人數，以及最多 3 筆紀錄（姓名、假別、時數，依假別著色），其餘顯示「還有 N 筆」
- 人員矩陣：每列一位員工、每欄一天；格內顯示假別簡字（特／事／病／生／公／遲／曠），放假日灰底
- 點一下日期（或矩陣格子），右側面板列出當天全部紀錄：
  - 每筆可以編輯、刪除；編輯時開啟與快速登記同一張假單，並帶入原有資料
  - 「在這天登記」：開啟快速登記並帶入日期
  - 上班日有「改為放假日」；放假日有「改為上班日」，且不能新增紀錄
  - 手動改為放假日或上班日時必須填原因（最多 100 字），可從快選清單選（預設：颱風停班、公司自訂休假、補班、公司活動，可在制度與設定修改）；改回與政府日曆相同時視為還原，原因一併清除
  - 當天已有紀錄時不能改為放假日，須先刪除紀錄
- 時數 = 請假時段與工作時段的重疊時數（扣除午休）；特休依第 3 節以半天計
- 防呆：同一位員工同一天的請假時段不能重疊；時數為 0 不能存檔

## 8. 假別
| 假別 | 給薪比例 | 最小單位 | 限制 | 雙重確認（預設） |
|---|---|---|---|---|
| 特休 | 1.0 | 半天（上午、下午各 4h；全天 8h） | 剩餘額度不夠時不能登記；該週年期間已結算後不能再登記 | 開 |
| 事假 | 0 | 30 分鐘 | | 開 |
| 病假 | 0.5 | 30 分鐘 | | 關 |
| 生理假 | 0.5 | 30 分鐘 | 只有女性可以選 | 關 |
| 公假 | 1.0 | 30 分鐘 | | 關 |
| 遲到 | 0 | 1 分鐘 | 起固定為 09:30，沒有分鐘上限，實際到班時間最晚 18:30 | 關 |
| 曠職 | 0 | 30 分鐘 | 沒有請假也沒有到班的缺勤；時段選法同事假 | 開 |

- 除了特休，其他假別不擋額度
- 遲到依實際分鐘數扣款（勞基法 §22、§26：不得超過實際未工作時間的比例）；遲到的分鐘數從 09:30 算到實際到班時間，扣除午休（12:00～13:30），沒有上限
- 沒有請假也沒有到班的缺勤，以曠職登記；出缺勤月曆上方有「曠職快速導覽列」，列出當月（依員工篩選）的曠職紀錄，點一筆就開啟編輯，方便事後補請假時快速找到並改成正確的假別

## 10. 員工個人頁
- 基本資料，以及「編輯資料」「登記請假」按鈕
- 數字卡：特休剩餘（本週年期間與剩餘天數）、本年請假合計（其中特休）、本年扣除金額（依假別拆分）、本年遲到次數與分鐘數
- 全年假勤圖：12 個月 × 31 天，每格依假別著色，滑過顯示假別與時數；週末與放假日深灰，今天加外框
- 最近紀錄：日期、假別、時間、時數、扣除金額、理由
- 特休週年紀錄：每個週年期間的額度、剩餘與處理結果（換錢金額／遞延／歸零／已休完）

## 11. 請假總覽
- 區間有兩種，畫面與匯出 Excel 用同一個區間：
  - 月結區間（預設）：結算日為每月 22 日，「N 月」= 上月 23 日 ～ N 月 22 日（例：10 月 = 9/23～10/22；1 月 = 前一年 12/23～1/22）；選「全年」= 前一年 12/23 ～ 當年 12/22；預設為今天所屬的月結月份（23 日起算入下個月）
  - 指定區間：自選起日、迄日（含頭尾），起日不能晚於迄日
- 畫面顯示目前區間的起訖日；匯出檔名為 `請假總覽_起日~迄日.xlsx`
- 首頁「本月」數字、出缺勤月曆、員工個人頁仍以曆月計算，不受月結區間影響
- 頂部合計卡：各假別總時數（遲到以分鐘計）
- 每位員工一列：假別分布長條、各假別時數、扣除金額合計、特休剩餘；表尾為合計列
- 點一下某列可以展開當期明細
- 匯出 Excel（.xlsx）：按「匯出 Excel」開啟選項視窗，選「匯出內容」與「匯出對象」；區間沿用頁面上的月結區間／指定區間
  - 金額試算總覽：每位員工一列，欄位為姓名、性別、本薪、假別、時數、扣款金額、總扣款金額；同一員工多個假別在同一格內分行，全部置中、凍結標題列，最後一列為合計
  - 請假明細總覽：一筆紀錄一列，欄位為姓名、部門、日期、假別、時間、時數（遲到以分鐘、特休以天），依員工、日期排序，最後一列為合計筆數
  - 匯出對象：全部員工、勾選部門（含「未設定部門」）、勾選人員；視窗顯示將匯出的人數與筆數，沒有選任何人時不能匯出
  - 檔名：`請假總覽_起日~迄日.xlsx`、`請假明細總覽_起日~迄日.xlsx`
- 員工主檔的匯出為 CSV（UTF-8 BOM，Excel 開啟不會變亂碼）；以 = + - @ 開頭的文字前加單引號，避免被當成公式
- 遲到以分鐘顯示

## 11-1. 備忘錄
- 側邊選單「備忘錄」：一個自由文字記事本，停止輸入 0.8 秒後自動儲存，離開頁面或關閉分頁前也會補存；最多 20000 字
- 內容存在資料檔（`app_setting.memo`），隨資料檔一起備份；標準版同樣存資料庫
- 另一個分頁已開啟同一份資料（唯讀）時不能編輯

## 12. 制度與設定
- 內容直接取自系統規則設定，規則修改時自動同步
- 可修改：部門清單（新增、改名、刪除；還有員工的部門不能刪除）、各假別的「送出前雙重確認」、特休到期提醒天數（14／30／60 天）、特休追蹤起算日（第 13 節）、手動改日原因的快選清單
- 唯讀：上班時間、月結區間（上月 23 日 ～ 本月 22 日）、扣款公式與範例、假別（給薪比例、最小單位、限制）、特休核給表
- 行事曆：各年度匯入狀態（匯入日期、手動改過幾天）與上傳
- 輕量版：資料夾位置、資料檔大小、最近備份時間、保留份數；「立即備份」「匯出給標準版」「換資料夾」
- 標準版：最近一次備份的時間與結果；「匯入輕量版資料檔」（限系統管理者）

## 13. 特休到期處理
- 週年到期時剩餘時數大於 0，出現在首頁提醒，由人資選擇：
  - 換錢：剩餘時數 × 處理當下的時薪（當下本薪 ÷ 30 ÷ 8），列入下一期薪資加項
  - 遞延：本期剩餘延長一年（記為下一期的遞延時數）；上期遞延過來、尚未用完的額度此時一律換錢；遞延額度到期時只能換錢
  - 歸零：需公司全體同意；選擇時再提示一次「可能違反勞基法 §38 第 4 項」（此風險已由公司接受）
- 請特休時，先扣未到期的遞延額度，用完再扣本期額度；扣用情形依紀錄日期先後自動計算，不另外存
- 離職時，剩餘特休（含遞延額度）一律換錢
- 每次處理存一筆 `annual_settlement`，記下處理方式、金額、時間；標準版另記處理人；同一員工同一週年期間只能有一筆
- 特休追蹤起算日（`annual_track_from`，預設為系統建立資料檔當天）：最後一天早於這天的週年期間視為已在系統外處理，不出現在提醒

## 15. 資料表
- `employee`：id、name、gender、salary、hire_date、annual_base_date、leave_date、email、phone、department_id（可為 NULL）、created_at、updated_at
- `department`：id、name（不可重複）
- `leave_record`（一天一筆）：id、employee_id、date、type_code、start_time、end_time、hours、deduction（存檔時算好，不取整）、salary（登記當時的月本薪）、reason、created_at、updated_at；索引 (date)、(employee_id, date)
- `leave_type`：code、name、pay_ratio、unit_minutes（特休 240）、segment_only、female_only、max_minutes、confirm_twice、color、sort_order
- `annual_settlement`：id、employee_id、period_start、period_end、remaining_hours、action（cash／defer／zero）、amount、deferred_hours（遞延到下一期的時數）、deferred_until、decided_at；UNIQUE (employee_id, period_start)
- `calendar_year`：year、source_file、uploaded_at
- `calendar_day`：date、year、gov_holiday、override（空值＝沒改過）、override_reason（手動修改原因）
- `app_setting`：key、value
  - work_start、work_end、lunch_start、lunch_end、hours_per_day（目前僅供參考，規則以程式常數計算）
  - annual_remind_days（到期提醒天數）、backup_keep（輕量版備份保留份數）
  - annual_track_from（特休追蹤起算日）、day_reasons（手動改日原因快選，JSON 陣列）
  - memo（備忘錄內容，純文字，最多 20000 字）
- 輕量版以 `PRAGMA user_version` 記錄 schema 版本，開啟資料檔時依序套用 migration（目前為第 8 版）
- 標準版另有：
  - `app_user`：id、username、display_name、password_hash、role（ADMIN／HR／VIEWER）、active、must_change_password、failed_count、locked_until、last_login_at、created_at
  - `leave_record`、`annual_settlement` 加 created_by／updated_by／decided_by
- 型別對照：日期 SQLite TEXT `YYYY-MM-DD` ↔ PostgreSQL date；金額 INTEGER ↔ integer（`leave_record.deduction` 不取整，用 REAL ↔ numeric(12,4)）；時數與比例 REAL ↔ numeric(4,2)；布林 INTEGER 0／1 ↔ boolean
- 員工有紀錄時不能刪除（第 9 節）；輕量版資料表的外鍵為 ON DELETE CASCADE，刪除限制由系統檢查；標準版的 PostgreSQL 外鍵改用 ON DELETE RESTRICT，由資料庫一併擋下

## 16. 資料移轉
- 舊版 `data/db.json` → 輕量版：在「制度與設定」執行一次匯入
  - employees → employee（特休年資起算日 = 到職日）
  - leaves → leave_record（時數與扣除金額依目前規則重新計算，不採用檔案中的數字；salary 填該員工在舊版的月本薪）
  - calendars → calendar_year ＋ calendar_day（保留手動修改）
  - 匯入前比對筆數，匯入後顯示結果
  - 開發與驗證一律使用測試資料，不直接拿正式資料測試
- 輕量版 → 標準版：系統管理者上傳 `sf_erp.sqlite` 整批轉入，只能匯入到空的資料庫
