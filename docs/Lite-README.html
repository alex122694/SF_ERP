SF ERP Lite 使用說明

SF ERP lite 是給一位人資在一台電腦上使用的出缺勤與請假管理工具：登記請假與遲到、自動算出扣款、依勞基法追蹤特休與到期處理。不用安裝、不用網路、不用登入，資料只存在你選的資料夾裡。

環境需求 第一次安裝 每天使用 常見作業 資料與備份 多分頁與多台電腦 從舊版移轉 疑難排解 開發與打包

環境需求

瀏覽器Chrome 或 Edge桌面版，建議最新版（至少 103）
作業系統Windows 10／11macOS、Linux 的桌面版 Chrome 也可以
網路不需要完全離線運作，不會上傳任何資料
安裝不需要解壓縮即可用，不需系統管理員權限
磁碟空間約 50 MB 以內程式 1.3 MB；資料檔通常幾 MB，另有最多 30 份備份
另外準備辦公日曆表 xlsx行政院人事行政總處每年公布

瀏覽器支援

瀏覽器可否使用說明
Microsoft Edge（桌面）可以Windows 內建，建議優先使用
Google Chrome（桌面）可以
Firefox、Safari不行不支援讀寫電腦上的資料夾，開啟後會顯示「這個瀏覽器不能存取資料夾」
手機、平板瀏覽器不行同上
無痕視窗不建議關閉後瀏覽器不會記住資料夾，每次都要重新選擇

lite 用到瀏覽器的資料夾讀寫（File System Access API）、IndexedDB、BroadcastChannel 與檔案解壓縮功能，Chrome／Edge 103 以後的版本都具備。

資料夾放哪裡

  • 建議放在本機硬碟的固定位置，例如 D:\SF ERP。移動資料夾後，下次開啟要重新選擇一次。
  • 可以放在雲端同步資料夾（OneDrive 等）或網路磁碟，但同一時間只能有一台電腦開啟，見「多分頁與多台電腦」。

第一次安裝

解壓縮 SF ERP-lite.zip 後會得到這個資料夾：

SF ERP\ ├─ index.html 程式本體（單一檔案，用 Edge／Chrome 開啟） ├─ 使用說明.txt └─ data\ 第一次開啟時選這個資料夾 ├─ sf_erp.sqlite 資料檔，系統自動建立 ├─ backup\ 每天自動備份，保留 30 份 └─ .lock 使用中標記，關閉頁面時自動刪除
  1. 把 SF ERP 資料夾放到固定位置例如 D:\SF ERP。之後不要再移動。
  2. 用 Edge 或 Chrome 開啟 index.html在檔案總管對 index.html 按右鍵 →「開啟檔案」→ 選 Microsoft Edge 或 Google Chrome。可以把這個頁面加入書籤，之後從書籤開啟。
  3. 按「選擇資料夾」，選 SF ERP\data瀏覽器問「要允許編輯檔案嗎？」時選「允許」。系統會在裡面建立 sf_erp.sqlite 與 backup\。
  4. 匯入今年的辦公日曆表到「制度與設定」→「行事曆」上傳人事行政總處的「政府行政機關辦公日曆表.xlsx」。還沒匯入的年度不能登記請假。
  5. 新增員工到「員工」按「新增員工」，填姓名、性別、月本薪、到職日。特休年資起算日不填時等於到職日。
  6. （選用）調整制度設定在「制度與設定」設定各假別是否要雙重確認、特休到期前幾天提醒（14／30／60 天）、手動改放假日的原因快選。
之後每次開啟開啟 index.html，畫面顯示「歡迎回來」與上次的資料夾，按 允許存取並開啟 即可。瀏覽器基於安全規定，每次都會要你按一次允許。

每天使用

左側選單有六個頁面。側欄下方會顯示資料檔名稱與「已自動儲存 · 時間」；每次修改都會立即存檔，不需要另外按儲存。

首頁

今天是上班日或放假日、在職人數、本月請假時數與扣款、今天不在座位的人、本週每天請假人數，以及待處理的特休到期提醒。

快速登記

一張假單登記一天：日期、員工、假別、時段、理由。右側即時試算時數、時薪、扣除金額與特休剩餘。

出缺勤月曆

月曆或人員矩陣檢視。點一下日期，右側列出當天紀錄，可以編輯、刪除、在這天登記，或把這天改為放假日／上班日。

員工

搜尋、依在職狀態篩選、排序、匯出 CSV。點進個人頁可看年資、特休進度、全年假勤圖、最近紀錄與特休週年紀錄。

請假總覽

選年度與月份（或全年），看各假別合計與每位員工的時數、扣款；可展開明細，並匯出 Excel。

制度與設定

上班時間、扣款公式、假別與特休核給表；行事曆匯入；資料檔與備份；匯入舊版資料。

登記規則重點

假別給薪時段限制
特休全薪全天（8 h）、上午或下午（各 4 h）剩餘額度不足、或該期已結算時不能登記
事假不支薪每 30 分鐘一格沒有請假的缺勤也以事假登記
病假半薪每 30 分鐘一格
生理假半薪每 30 分鐘一格只有女性員工可以選
公假全薪每 30 分鐘一格
遲到不支薪從 09:30 起算，填實際到班時間最多 30 分鐘；超過請改登記事假
  • 上班時間 09:30～18:30，午休 12:00～13:30。請假時數只算與上班時段重疊的部分。
  • 扣除金額 ＝ 時數 × 時薪 ×（1 − 給薪比例），時薪 ＝ 月本薪 ÷ 30 ÷ 8，每筆四捨五入到元。
  • 放假日、員工到職前或離職後、同一人同一天時段重疊，都不能送出；錯誤會直接顯示在假單上。
  • 特休數字後面的「天」可以點一下切換成小時顯示。

常見作業

員工離職

到員工個人頁按「編輯資料」，填寫離職日。離職後不會出現在登記名單，出缺勤紀錄、扣款金額與特休處理紀錄都會保留。剩餘特休會出現在首頁提醒，只能選換錢。

刪除員工

只有沒有任何紀錄的員工（例如建錯的資料）可以刪除。已有出缺勤或特休處理紀錄的員工按「刪除」時，系統會說明不能刪除，並提供「填寫離職日」。

修改或刪除一筆紀錄

到出缺勤月曆點那一天，在右側按「編輯」或「刪除」。編輯時扣款以該筆登記當時的月本薪重新計算，之後的調薪不會影響舊紀錄。

特休到期處理

週年到期前會在首頁提醒（預設 30 天內）。可選「換錢」（剩餘時數 × 當下時薪，列入下一期薪資）、「遞延一年」或「歸零」。遞延過來的額度到期時只能換錢；選歸零會再提醒一次可能違反勞基法 §38 第 4 項。

颱風假、公司自訂休假、補班

到出缺勤月曆點那一天，按「改為放假日」或「改為上班日」，並填寫原因（可從快選清單選）。改過的日子標示「手動」，可以「還原為政府日曆」。當天已有紀錄時要先刪除紀錄才能改為放假日。

每年 10 月匯入明年行事曆

每年 10 月 1 日起，首頁會提醒上傳下一年度的辦公日曆表。重新上傳同一年度時，手動改過的日子不會被覆蓋。

匯出報表

請假總覽可匯出 Excel（每位員工一列，最後一列為合計）；員工主檔可匯出 CSV，用 Excel 開啟不會亂碼。

資料與備份

  • 自動備份：每天第一次存檔前，系統把前一份資料檔複製到 data\backup\sf_erp-YYYYMMDD.sqlite，保留最近 30 份。
  • 立即備份：「制度與設定」→「資料檔與備份」→ 立即備份，寫入今天的備份檔（同一天重複會覆蓋）。
  • 完整備份：關閉 SF ERP 後，把整個 data 資料夾複製到隨身碟或其他位置。
  • 還原：關閉所有 SF ERP 分頁，把 sf_erp.sqlite 改名保留，再把要還原的備份檔複製一份到 data\ 並改名為 sf_erp.sqlite，然後重新開啟。
  • 換資料夾：「制度與設定」→ 換資料夾，回到選擇資料夾的畫面。
  • 存檔失敗時：畫面會顯示紅色提示，這次修改不會寫入，資料檔維持上一次成功存檔的內容。請確認磁碟空間與資料夾權限後再操作一次。
資料只在這個資料夾裡刪除或格式化 data 資料夾就會失去所有資料。請定期把整個資料夾另外複製一份。

多分頁與多台電腦

  • 同一個瀏覽器開第二個分頁：第二個分頁會自動變成唯讀，畫面上方有黃色提示。請回到第一個分頁操作。
  • 別台電腦開啟同一個資料夾：如果 3 分鐘內有另一台電腦或另一個瀏覽器在使用，會顯示「這個資料夾可能正在別處使用」，可選擇「唯讀開啟」或「我確定沒有人在用，開啟」。
  • 兩邊同時修改時，後存的會蓋掉先存的。同一時間只讓一台電腦開啟同一個 data 資料夾。

從舊版移轉

  1. 先備份舊版的 data\db.json。
  2. 在新的空白資料夾開啟 lite，不要先新增員工或紀錄。
  3. 「制度與設定」→「匯入舊版資料」→ 選擇 db.json。
  4. 系統會轉入員工、紀錄、各年度行事曆與手動修改，完成後顯示筆數。時數與扣款依目前規則重新計算；任何一筆有問題就整批取消，資料檔不會留下一半的資料。

只能匯入一次，且只能匯入到沒有員工與紀錄的資料檔。要給標準版使用時，可用「匯出給標準版」下載目前的 sf_erp.sqlite。

疑難排解

顯示「這個瀏覽器不能存取資料夾」

目前的瀏覽器不支援。請在檔案總管對 index.html 按右鍵 →「開啟檔案」→ 選 Edge 或 Chrome。

顯示「沒有取得資料夾的讀寫權限」

瀏覽器詢問時選了「不允許」。再按一次 允許存取並開啟，並選「允許」。

顯示「上次的資料夾無法開啟」

資料夾被移動、改名或刪除。按 選擇其他資料夾，選新的位置。

畫面上方顯示這個分頁是唯讀的

同一個瀏覽器已有另一個 SF ERP 分頁。回到那個分頁操作，或把它關閉後重新整理這一頁。

不能登記，提示「請先匯入 XXXX 年行事曆」

到「制度與設定」上傳該年度的辦公日曆表。

上傳行事曆時顯示「無法辨識辦公日曆表格式」

請使用人事行政總處公布的原始 xlsx，不要另存或修改版面。檔案上限 10 MB。

顯示「資料檔損毀或不是 SF ERP 的資料檔」

依「資料與備份」的步驟，從 backup\ 還原最近一份備份。

開發與打包

這一節給負責維護程式的人。一般使用者不需要。

項目需求
Node.js20.19 以上或 22.12 以上（Vite 7 的要求），附帶 npm
原始碼web/：React 18、TypeScript 5、Vite 7、sql.js、Vitest 4
瀏覽器Chrome 或 Edge，用來測試資料夾讀寫

在 web 資料夾執行：

指令用途
npm ci依 package-lock.json 安裝套件（第一次或套件版本不符時）
npm run dev開發伺服器（http://localhost:5173）；本機開發時多一個「使用瀏覽器內部儲存（測試用）」，不會碰到任何資料夾，並可在設定頁載入範例資料
npm test執行單元測試（規則、資料庫、xlsx、翻譯完整性）
npm run build型別檢查並建置單一檔 dist/index.html（JS、CSS、WASM 全部內嵌，含 CSP）
npm run lite建置並更新 release/SF ERP-lite/SF ERP/（index.html、data\、使用說明.txt；不會清空 data）
npm run package同上，另外打包成 release/SF ERP-lite.zip
 
cd web
npm ci
npm test
npm run package

開發與驗證一律使用測試資料，不要直接拿正式的 data 資料夾測試。系統規格見 docs/規格.md。
